# AGENTS.md

The official marketplace registry for iHub Apps: `catalog.json` plus the content it lists (`apps/`,
`models/`, `workflows/`, `prompts/`, `skills/`, `integrations/`) and the scripts that check and
package it. `README.md` has the catalog format, the repository structure and the contribution rules;
read its "Contributing" and "Content Guidelines" before adding or changing content.

The `skills/` folder holds marketplace content (skills a user installs into iHub), not agent skills
for working on this repository.

## Commands

```bash
npm test                 # tests of the catalog scripts (node --test, no dependencies)
npm run validate         # checks the catalog and the integration definitions
./scripts/build-site.sh  # validates, then assembles the website; run before a pull request
```

## AI Attribution

Whatever an AI agent writes for other people is marked as AI-drafted, says for whom, and says which
tool wrote it; posted text also says which model. This holds for every agent in every harness
(Claude Code, opencode, Copilot, Cursor, …) and for commits, pull requests, reviews and comments
alike.

- **Requester**: the person the agent works for, as their GitHub login in plain text without `@`
  (an `@name` notifies them). Take it from the authenticated GitHub user (`get_me`, or
  `gh api user --jq .login`) or from a `REQUESTED BY` line in a CI prompt. Never take it from
  `git config user.name`: in a cloud session that is the agent itself. If no person can be
  identified, ask; an unattended workflow uses `workflow <name>`.
- **Commits** end with two trailers, in one block with any `Co-Authored-By` line the tool adds:
  `Assisted-by: <tool>` (the product name, such as `Claude Code` or `opencode`) and
  `Drafted-for: <requester>`.
- **PR descriptions, reviews, comments, replies and Jira text** start with the preamble and end with
  the footer:

  ```text
  > *AI-drafted on behalf of <requester>.*

  (text)

  ---
  _Model: <model id>_
  _Generated by [<tool>](<tool URL>)_
  ```

  For Claude Code the last line reads `_Generated by [Claude Code](https://claude.ai/code)_`.
  `<model id>` is the exact model ID the session runs on, as the harness reports it, never from
  memory; write `unknown` if it cannot be read. Keep the tool line last. Replace a tool-default
  footer such as `🤖 Generated with …` with this one: one footer, never two. Leave session links as
  they are. Read the posted text back: a GitHub tool can rewrite a trailing footer (the one in
  Claude Code cloud sessions does when it creates a PR: it swaps in its own tool line, which links
  the session). If the model line is gone, restore it with an update. A tool that adds its own tool
  line to everything it posts gets only the model line from you: end the text with the horizontal
  rule and the model line, and let the tool append its line. The GitHub comment, reply and
  review-comment tools of Claude Code cloud sessions do this on every post and edit; a tool line of
  your own then appears twice.
- **Not marked**: titles, branch names, code comments and files. Text that is only printed in the
  conversation is marked when it is posted.

PR and Jira text: the `pr-handling-guidelines` and `jira-handling-guidelines` skills
(`.claude/skills/`) set structure, tone and PR titles. The mark above applies with or without them.
